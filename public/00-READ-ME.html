TC Connect
One folder. Test first. Deploy later.

The complete frontend, backend, database setup, files and instructions are included. Begin with local testing below.

1. Start on your Windows computer

  1. Install Node.js 24 or newer once. Use the Windows installer and keep its PATH option enabled.
  2. Right-click TC-Connect-Voice-v4.zip → Extract All. Open the extracted TC-Connect-Voice-v4 folder.
  3. Double-click 01-FIRST-RUN.cmd. Stay connected to the internet during this first installation. The installer downloads dependencies and builds the interface. It reports errors in logs/install.log or logs/build.log if anything fails.
  4. The launcher opens your browser automatically. Create your administrator name, email and password in its setup page.
  5. Sign in. Start with Department settings to create years/groups, then use People & access to add staff and approve students.
After installation: double-click 02-START.cmd. Keep its window open while using the system. You do not type commands. Core workflows work offline after installation.

The working application opens at an address such as http://127.0.0.1:4310. That is your computer's backend. Opening index.html directly cannot run accounts or the database; it now shows launch instructions instead of an empty page.

2. Create your real test workspace

  1. As administrator, create Year 1 / Group A and Year 2 / Group B, or your department's actual structure.
  2. Create a lecturer and assign Year 2 / Group B. Give the lecturer a temporary password. The lecturer changes it when signing in.
  3. In a different browser/profile, register a student with full name, student number, email and Year 2 / Group B. Register a Year 1 student as well to test restrictions.
  4. As administrator, approve both registrations after checking their details.
  5. As lecturer, create a module such as Computer Mathematics for Year 2 / Group B.
Use separate browser profiles, different browsers, or a regular window and a private window for simultaneous roles. Ordinary tabs share the same sign-in. No fake accounts or default passwords are included.

Saved data

Accounts, messages and uploaded files live in local-data. Keep this folder when updating. Stop the launcher before backing up or moving the whole folder.

Stopping and restarting

Close the launcher window, or press Ctrl+C, to stop. Run 02-START.cmd to reopen the same workspace. A new Railway service gets its own independent database. If updating an existing local installation, stop it and copy the entire local-data folder into this new project folder before starting. The new extension/call migration runs automatically.

3. Test the workflows before hosting

This checklist is a reading aid; the HTML file does not store these checkbox selections. Core flows use the real local database and backend.

4. Test private voice calls inside the app

Every registered account receives an automatic TC Connect extension, such as 610002. It is an app identifier, not an MTC/mobile telephone number. It is linked to the person's saved full name, student number, year, group and photograph.

  1. Open two separate browser profiles/browsers on the same computer. Sign in as the caller and recipient. Both accounts must be approved.
  2. Click Enable incoming call sounds once in each browser. This unlocks audio under the browser's autoplay rules.
  3. Open a student request as its responsible staff member and click Dial student / requester. A student can call assigned staff from the request. You can also use Dial on an authorised profile or find a permitted person by extension in Calls.
  4. Allow microphone access. The recipient receives a private incoming call screen, showing the caller's registered identity. Choose Answer or Decline.
  5. With both microphones allowed, test speech in both directions, Mute/Unmute, and End call. Use headphones or two physical devices for a realistic sound test; two open microphones/speakers on one desk can cause echo.
  6. Check that a third signed-in user receives no ringing notification or access to that call's signaling/history. Calls follow existing academic/support relationships.

The browser supplies microphone capture with echo cancellation, noise suppression and automatic gain control. The call timer starts only after both WebRTC peers report a connected audio transport. Call setup is not labelled as a connected call.

For internet calls between different networks: configure a TURN relay. Set TURN_URLS to the provider's turn:/turns: URLs, and either TURN_SECRET or TURN_USERNAME plus TURN_PASSWORD. Put these values in .env.local for local testing or Railway Variables for hosting, then restart. The web application does not host a TURN server itself. No provider account or working relay secrets are included.

Both users need the app open and signed in. Closed-browser push notifications, voicemail and PSTN/mobile telephone calls are not included. No WhatsApp or mobile dialler is opened. Only the two participants can retrieve that call and its history; administrators do not get a bypass to private calls.

Same-computer local testing can use direct ICE connections without an external relay. Network policies can still block direct browser media. The cloud verification browser used during development supplied no usable ICE candidates, so the automated synthetic-audio trial could not establish a media path there. Backend privacy/control tests passed, but a real microphone conversation must be verified on your devices and configured network before rollout.

5. Enable and test live lessons

Real multi-person video/audio uses a conferencing media service. You can run the department application locally while it connects to that online service.

  1. Create a LiveKit Cloud project, or use a separately secured compatible LiveKit server.
  2. Copy .env.local.example to .env.local. Add your LiveKit WebSocket URL, API key and API secret. Keep that file private.
  3. Restart 02-START.cmd with internet access.
  4. As lecturer, schedule a lesson for a module/year/group, start it and join. Students ask to join; the host admits or declines them.
  5. Enable microphones/cameras. Share a screen/window to present slides. Test the persistent lesson chat, host mute/removal, ending for everyone and attendance export.
The application includes the conferencing integration. It cannot provide live media without a configured media service. Participant capacity depends on your service quota, devices and network; the default room ceiling is 100. Live audio/video was not verified against your own media account here.

This is a Google Meet-style lesson section. It does not include every Google Meet feature: recording, captions, breakout rooms and telephone dial-in are outside this release. The former Local device checks page has been removed. Camera and microphone controls are inside actual live sessions and private voice calls.

6. Deploy the same source to Railway

  1. Upload the contents of TC-Connect-Voice-v4 to a private GitHub repository. Put Dockerfile, railway.json and package.json at the repository root. Include the server, src, scripts and public folders. Do not upload node_modules, local-data, logs or real .env files.
  2. In Railway, create a project and deploy from that repository. The Dockerfile builds the interface and backend together.
  3. Attach a persistent Volume mounted at /data. Use one replica; this edition uses SQLite on that volume.
  4. In Networking, generate a public HTTPS domain. Set APP_URL to its exact HTTPS origin. You can configure the domain before the first successful app start.
  5. Add the variables below in Railway Variables. Railway supplies PORT automatically.
  6. Redeploy. The service health check is /health; the database is initialised during application startup, when the volume is mounted.
  7. Open the Railway domain and sign in using the administrator credentials you configured. Change the temporary password, then create the department's structure and accounts.
  8. Configure volume backups and run the same role/access and media checks on the deployed service before the college rollout.

ADMIN_PASSWORD creates the founding administrator only when the database is empty. Updating that variable does not reset an existing account. After setup, change the password in My profile and remove the initial value from Railway Variables.

Local test records are not uploaded automatically. The /data volume holds the production database and files. eLearning/TCMS directory entries open their existing services; internal platform records are not synchronised without authorised integration.

If the screen does not open

First: keep the launcher open and use the exact browser address it prints.

Missing files: run 01-FIRST-RUN.cmd. A startup check now verifies the built JavaScript and CSS files. Windows paths with spaces are included in the path-handling tests.

Installation/build fails: open logs/install.log or logs/build.log for the actual error.

Registration has no groups: the administrator must create years/groups before students register.

No private call audio: allow the microphone, click Enable incoming call sounds, check the output volume, and configure a TURN relay when calling across networks. The local test browser address must come from the launcher; hosted access must use HTTPS.

No live video: check .env.local, restart, connect to the internet and allow browser camera/microphone access.

Unexpected interface error: the application now displays an error screen with a reload button, rather than silently showing an empty root.
